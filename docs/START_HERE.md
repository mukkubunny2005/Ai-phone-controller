# AI Phone Controller — Start Here

This repository now contains the Flutter chat app, Kotlin Android bridge, Accessibility Service, offline model runtime, and the build overlay.

## Fixed project requirements

- Android 15 target, no root.
- Flutter UI + Kotlin native Android integration.
- Existing pretrained text-only model; no custom training or fine-tuning.
- Offline inference after the model is downloaded.
- Accessibility UI tree only. Never capture screenshots.
- User-visible actions only, with confirmation before execution.
- Password, PIN, OTP and identifiable payment-detail fields are excluded.
- Text input and optional on-device voice input.
- Windows laptop + VS Code/Flutter development; physical Android phone for device testing.

## Included capabilities

- Open installed apps by their launcher names.
- Read accessible screen labels, tap controls, enter text in safe editable fields, and scroll.
- Back and Home navigation.
- Open selected Android settings pages without silently changing their values.
- Multi-step workflows and offline AI planning, each limited to eight steps.
- Cancel an active workflow.
- YouTube foreground text-signal protection that warns and returns Home when a limited inappropriate-content signal is exposed by the accessibility tree.

## Important boundaries

- YouTube protection cannot inspect video imagery without screenshots; it may miss content and can produce text-based false positives.
- A normal third-party app cannot guarantee force-stopping another app or removing it from Recents.
- On-device voice recognition requires Android 12+ and an installed offline speech recognition service/language pack. The microphone is requested only after the user taps the microphone button.
- The local Qwen2.5 1.5B model is approximately 1.6 GB and requires additional RAM while loaded. No API key is required.
- Physical-device testing is still required for accessibility behavior, offline speech availability, model loading/performance, and app compatibility.

## Build and test

From the repository root in a Windows terminal with Flutter and Java 17 installed:

```powershell
bash tool/prepare_android.sh
flutter pub get
flutter analyze --fatal-infos --fatal-warnings
flutter test
flutter build apk --debug
```

The Android scaffold is regenerated by `tool/prepare_android.sh`. Make durable native changes in `tool/android_overlay`, then regenerate Android files.

## First-run checklist

1. Install the debug APK.
2. Review the Accessibility disclosure and enable the service in Android Settings.
3. Download the offline model over Wi-Fi after confirming the size.
4. Load the model.
5. Try a harmless command such as `open Chrome`, `read screen`, or `scroll down`.
6. Tap the microphone only if you want voice input and your phone supports offline speech recognition.
7. Test YouTube text-signal protection with safe, controlled test labels. Do not assume it detects video frames.
